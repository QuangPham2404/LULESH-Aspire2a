## Build Errors And Fixes

Build debugging happened over several attempts. The detailed raw build records
are on Aspire2A under:

```text
builds/build-scripts/CCE13-CrayMPICH8/records/
```

Important lessons:

- The PBS job environment did not have `git` on `PATH`, even though the login
  environment did.
- Future build workflow should clone or prepare source on the login node before
  submitting the PBS build job.
- PBS build jobs should not require `git` unless the environment has been
  explicitly verified.
- A first PATH patch added `/usr/bin` before the Cray wrapper paths. This made
  lowercase `cc` resolve to system `/usr/bin/cc` instead of the Cray wrapper.
- Preserve Cray wrapper priority in `PATH`. If system paths are needed, append
  them instead of prepending them.
- The build also failed once because PBS default memory was only `10mb`, causing
  CMake to be killed by cgroup OOM.
- The PBS build script now requests `mem=4gb`.

The build eventually succeeded after these fixes.

## Git And Sync Notes

Local-to-Aspire2A handoff was exercised:

1. Write scripts locally.
2. Commit locally.
3. Push to GitHub.
4. Pull with `git pull --ff-only` on Aspire2A before running.

During result sync back to local, a useful issue appeared:

- The smoke-test `.o` file was initially hidden by the global `*.o` ignore rule.
- `.gitignore` was updated so PBS `.o` logs under `experiments/` are trackable.
- When pulling results back onto Aspire2A, the remote clone already had the same
  `.o` and `.e` files as untracked outputs. Git refused to overwrite them.
- The files were compared against `origin/main`, confirmed byte-identical, then
  staged on Aspire2A so the fast-forward pull could complete.

This suggests the future Aspire2A-to-local result workflow needs a cleaner rule
to avoid tracked-result conflicts with untracked remote outputs.
